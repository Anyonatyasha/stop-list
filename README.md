# Стоп-лист кухни

Веб-приложение для ресторана: позволяет временно снимать блюда с продажи («ставить в стоп») с указанием причины и срока, видеть активный стоп-лист с обратным отсчётом и досрочно возвращать блюда в продажу.

## Возможности

- Справочник блюд по категориям: Кухня, Бар, Десерты
- Постановка блюда в стоп-лист с причиной и сроком (от 15 минут до 12 часов)
- Активный стоп-лист с оставшимся временем, которое обновляется в реальном времени
- Фильтр стоп-листа по категории
- Досрочный возврат блюда в продажу
- Автоматическое снятие со стопа по истечении срока
- Валидация данных на клиенте и на сервере, единый формат ошибок API
- История завершённых записей с пагинацией (на уровне API)

## Стек

**Backend:** Node.js, Express, TypeScript
**Frontend:** React 18, Vite, TypeScript
**Инструменты:** npm workspaces, concurrently, tsx

## Как запустить

Требования: Node.js 18+, npm.

Проект поднимается одной командой из корня:

```bash
npm install
npm run dev
```

Открыть `http://localhost:5173`.

Сборка прод-версии:

```bash
npm run build       # собирает server и client
npm start -w server # запускает собранный сервер (dist/index.js)
```

### Переменные окружения

В каждом пакете есть `.env.example`. Скопируйте его в `.env`, если нужно изменить значения по умолчанию. Для локального запуска ничего менять не нужно.

**server/.env**
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | порт, на котором слушает API |

**client/.env**
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VITE_API_URL` | `/api` | базовый URL API. Значение по умолчанию работает с dev-прокси Vite; для отдельного деплоя клиента указать полный адрес сервера |

## API

Базовый префикс: `/api`. Формат ошибок везде одинаковый:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "reason должен содержать от 5 до 200 символов" } }
```

### `GET /api/dishes`

Справочник блюд.

Ответ `200`:
```json
[
  { "id": "d1", "name": "Борщ с говядиной", "category": "Кухня", "price": 420 },
  { "id": "d7", "name": "Мохито", "category": "Бар", "price": 350 }
]
```

### `GET /api/stop-list`

Активные записи стоп-листа (ещё не возвращены и не истекли). Опциональный фильтр `?category=Кухня|Бар|Десерты`.

Ответ `200`:
```json
[
  {
    "id": "5a1e...-uuid",
    "dishId": "d1",
    "reason": "Закончилась говядина",
    "stoppedAt": "2026-09-16T10:00:00.000Z",
    "expiresAt": "2026-09-16T12:00:00.000Z",
    "returnedAt": null,
    "dish": { "id": "d1", "name": "Борщ с говядиной", "category": "Кухня", "price": 420 },
    "status": "active",
    "minutesLeft": 87
  }
]
```

Ошибка `422` (неизвестная категория, `GET /api/stop-list?category=Стейки`):
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Некорректная категория" } }
```

### `POST /api/stop-list`

Поставить блюдо в стоп-лист.

Тело запроса:
```json
{ "dishId": "d1", "reason": "Закончилась говядина", "durationMinutes": 120 }
```
Правила валидации: `dishId` обязателен; `reason` — 5–200 символов; `durationMinutes` — целое число от 15 до 720.

Ответ `201`: объект записи (как в примере выше, `status: "active"`).

Ошибка `422` (не прошла валидация):
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "reason должен содержать от 5 до 200 символов" } }
```

Ошибка `404` (блюдо не найдено):
```json
{ "error": { "code": "DISH_NOT_FOUND", "message": "Блюдо unknown не найдено" } }
```

Ошибка `409` (блюдо уже активно в стоп-листе):
```json
{ "error": { "code": "DISH_ALREADY_STOPPED", "message": "Блюдо уже в стоп-листе" } }
```

### `PATCH /api/stop-list/:id/return`

Досрочно вернуть блюдо в продажу (снять со стоп-листа).

Ответ `200`: запись с `returnedAt` и `status: "returned"`, `minutesLeft: 0`.

Ошибка `404` (нет такой записи):
```json
{ "error": { "code": "ENTRY_NOT_FOUND", "message": "Запись 123 не найдена" } }
```

Ошибка `409` (уже возвращена или истекла):
```json
{ "error": { "code": "ENTRY_NOT_ACTIVE", "message": "Запись уже возвращена или истекла" } }
```

### `GET /api/stop-list/history`

История завершённых записей (возвращённых или истёкших), отсортированная по времени завершения: сначала новые. Параметры `?limit=1..100` (по умолчанию 20), `?offset=0..` (по умолчанию 0).

Ответ `200`:
```json
{
  "items": [
    {
      "id": "5a1e...-uuid",
      "dishId": "d3",
      "reason": "Испортилась партия",
      "stoppedAt": "2026-09-15T09:00:00.000Z",
      "expiresAt": "2026-09-15T11:00:00.000Z",
      "returnedAt": "2026-09-15T10:30:00.000Z",
      "dish": { "id": "d3", "name": "Стейк из лосося", "category": "Кухня", "price": 890 },
      "status": "returned",
      "minutesLeft": 0
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```

Ошибка `422` (некорректная пагинация, `?limit=0`):
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "limit должен быть целым числом от 1 до 100" } }
```

### Прочие ошибки

- `400 BAD_REQUEST` — битый JSON в теле запроса.
- `404 NOT_FOUND` — неизвестный маршрут.
- `500 INTERNAL_ERROR` — непредвиденная ошибка сервера.

## Архитектурные решения

- **Слоистая архитектура сервера.**
  - `domain` — только правила и расчёты, без зависимостей от Express и хранилища;
  - `repository` — только хранение данных;
  - `service` — вся бизнес-логика;
  - `routes` — принимают запрос, валидируют и вызывают сервис.
- **Хранилище за интерфейсом.** Данные хранятся в памяти, но доступ к ним идёт через интерфейсы `DishRepo` и `StopListRepo`. Чтобы подключить PostgreSQL или SQLite, достаточно написать новую реализацию репозитория: бизнес-логика не изменится.
- **Время как зависимость.** Сервис получает функцию `now()` извне, поэтому логику истечения срока легко тестировать без реального ожидания.
- **Статус вычисляется, а не хранится.** Запись становится «истёкшей» автоматически по `expiresAt`, без фоновых задач и cron.
- **Типизированные ошибки.** Каждая ошибка — класс с HTTP-кодом и машинным кодом (`DISH_NOT_FOUND`, `ENTRY_NOT_ACTIVE` и т. д.), а middleware превращает их в единый JSON-ответ.
